# 👥 תפקידים וסוכנים

איך העבודה בפרויקט הזה מחולקת לתפקידים, ומה כל תפקיד אחראי עליו.

---

## ⚠️ קודם כול — מה אלה באמת

**התפקידים למטה הם פרסונות, לא Agents.** ההבחנה חשובה כי היא קובעת מה קורה כשאתה כותב `FRONTEND` בהודעה:

| | פרסונה (מה שיש כאן) | Agent אמיתי |
| :--- | :--- | :--- |
| איפה מוגדר | הטבלה במסמך הזה | `.claude/agents/<name>.md` עם frontmatter |
| מה קורה בהפעלה | Claude קורא את השורה ומיישר לפיה קו | תהליך נפרד עם קונטקסט נקי משלו |
| מודל וכלים | של השיחה הנוכחית | ניתנים להגדרה לכל סוכן |
| עלות | אפס | טוקנים נפרדים לכל הרצה |
| רואה את השיחה | כן, כולה | לא — מתחיל מאפס |

**בפרויקט הזה לא מוגדר אף Agent, וזו בחירה.** לרוב המשימות פרסונה עדיפה: היא לא עולה טוקנים נוספים, והיא לא מאבדת את ההקשר שנצבר בשיחה. סוכן אמיתי משתלם רק כשהמשימה **רחבה וניתנת לבידוד** — סריקת קוד רוחבית, חיפוש בעשרות קבצים, סקירה עצמאית.

**Skills לא "שייכים" לסוכן.** אין מנגנון כזה. כל מי שיש לו את כלי ה-Skill יכול להפעיל כל skill מותקן. עמודת ה-Skills בטבלה היא **הנחיה** — "בכובע הזה, אלה הכלים שכדאי לשלוף" — ולא הרשאה טכנית.

## 🛠️ Skills מותקנים בפועל

14 חבילות, ב-`.agents/skills/`, עם קישור סימבולי מ-`.claude/skills` אליהן — **הקישור הזה הוא מה שהופך אותן לזמינות**. אם הן מפסיקות לעבוד, זה הדבר הראשון לבדוק.

```text
עיצוב וממשק:  brand · design · design-system · ui-styling · ui-ux-pro-max · web-design-guidelines
נתונים:        supabase · supabase-postgres-best-practices
React:         vercel-react-best-practices · vercel-composition-patterns · vercel-react-view-transitions
תשתית:         vercel-optimize · vercel-cli-with-tokens · deploy-to-vercel
```

**אל תערוך את הקבצים האלה.** הם מנוהלים דרך `skills-lock.json` ועריכה ידנית תישבר בעדכון הבא.

בנוסף זמינים כישורים גלובליים מתוספים מותקנים — בעיקר `superpowers` (תכנון, ניפוי שגיאות שיטתי, TDD) ו-`frontend-design`.

## 🤖 Agents אמיתיים שכן זמינים

מגיעים מהמערכת ומתוסף `pr-review-toolkit`, ולא מוגדרים בפרויקט:

| סוכן | מתי שווה להפעיל |
| :--- | :--- |

| `Plan` | לתכנן שינוי ארכיטקטוני לפני כתיבת קוד |

**כלל אצבע:** הפעל סוכן רק כשהמשימה מבודדת ורחבה. משימה שדורשת את ההקשר של השיחה — עדיף לעשות בפרסונה.

## 📐 חוקי עבודה החוצים את כל התפקידים

1. **דטרמיניזם** — אין `Math.random()` במנוע השיבוץ. לעולם.
2. **אילוץ קשיח קודם לכל** — שיבוץ או החלפה שמפרים חוק עבודה נדחים, גם כשהמשתמש מתעקש.
3. **ביטול במקום אישור** — פעולה מתבצעת מיד, עם `UndoBar` של 8 שניות. בלי `confirm()`.
4. **`npm test` ו-`npm run build`** חייבים לעבור אחרי כל שינוי.
5. **אימות בדפדפן** — "עובד" נאמר רק אחרי שראית את זה עובד. שלושה מבאגי ה-UX של אבן דרך א' נמצאו רק ככה.
6. **דיווח כן** — מה שלא נבדק מדווח כלא נבדק.
